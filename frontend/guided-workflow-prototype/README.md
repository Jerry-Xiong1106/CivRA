# CivRA 固定流程与案情参考 · 交互原型 v2.1

基于 `develop@922493e`，交付分支为 `codex/guided-workflow-case-visuals`。用于评审固定办理流程，以及法条、类案参考、案情图谱和案例统计界面。**没有修改 Python 后端，也尚未接入真实 Agent / RAG / OCR。**

## 启动

在本目录运行：

```sh
python -m http.server 8782 --bind 127.0.0.1
```

浏览器打开 `http://localhost:8782/`。Windows 可以运行 `启动预览.ps1`。无需安装 npm 包；按 Ctrl+C 停止服务。请选择 HTTP 预览，以获得稳定的浏览器本地存储行为。

案件演示数据保存在浏览器 `localStorage`，键为 `civra.guided-workflow.prototype.v2`。v2.1 保留已有 v2 案件并补充参考/关系字段；不同案件的收藏与材料分别保存。页面刷新后恢复案件内容，当前标签和临时筛选恢复默认值。

## 页面入口

七标签保持既定顺序：案情沟通 → 法律依据 → 维权路径 → 证据材料 → 结果分析 → 起诉状草稿 → 案情图谱。

- 案情沟通：三档字段规则、条件追问、未知及原因、用户确认；五步进度贯穿办理过程。
- 法律依据：10 条内置法条的主题/条号查询、原文与来源；相似案例筛选、详情、最多三例对比；本案收藏。
- 维权路径：当前案情满足规则且用户确认摘要后开放；实际程序与处理意向分开。
- 证据材料：仅登记名称、大小及用户标记的事实关联。
- 结果分析：案情确认后查看三类演示情形、待核实前提和本案记录，链接到材料及参考。
- 起诉状草稿：确认诉讼路径、适用角色与阶段后，确认正式表述并生成演示 Markdown。
- 案情图谱：案件时间线、主张与证据对应、案例统计。可以创建独立的图谱演示案件。
- 左侧“只咨询法律”：无需先收集完整案情，可查阅法律与案例展示。

## 建议试用

1. 第一个交通示例中点击维权路径，查看进入条件。回到案情沟通补信息，再确认摘要，选择并确认路径。
2. 使用“借款未归还 · 诉讼准备”示例查看草稿与结果页；修改关键事实后，后续操作要求重新确认。
3. 使用“已开庭 · 调解意向核对”示例，查看程序阶段与处理意向并存。
4. 法律依据搜索“第680条”或“医疗”，打开来源详情并收藏；选择无匹配词查看空态。
5. 相似案例中按类型、地区、法院、年份和结果筛选，查看理由与本案差异，加入对比。
6. 案情图谱 → 案例统计，观察筛选后的计数与六类分布同步更新。
7. 案情图谱 → 主张与证据 → 打开图谱演示案件，编辑多对多关系，刷新确认保留。

## 数据边界

- 自由对话只保存陈述，不运行模型，不自动确认结构化事实。
- 文件不上传服务器、不保存正文、不运行 OCR/重复票据识别；刷新后仍只保留登记信息。
- 法律页是本地关键词匹配。9 条民法典原文及 PDF 页码核对自仓库 `data/processed/civil_code.jsonl`，另含民事诉讼法第145条；“PDF 页码”指仓库 PDF，网页链接用于查阅官方全文。
- 36 条案例均为虚构的 UI 样本：交通事故 24 条、借贷 6 条、买卖 6 条，无真实案号或原文链接。统计仅描述模拟样本；不计算胜诉概率。
- 图谱关系由用户标记，或来自独立且明确标注的演示案件，不认定材料真实性或法律证明力。
- 结果分析为条件情形布局，不对本案作真实判断。
- 文书尚未填写法院原始表格；只演示 Markdown。正式 Word/PDF、费用计算和模板能力需接现有后端。
- 前端规则不能作为正式业务授权；服务端必须统一校验。首轮起诉状只演示交通/借贷/买卖、提出请求方、尚未起诉的范围。
